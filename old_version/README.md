# drawing_util — AI 像素画工坊（浏览器版）

给定用户对话，调用 **DeepSeek** 实现 `prompt.md` 描述的“生图”功能（模型生成受约束的像素网格代码），
程序端解析、校验并**自动生成 PNG 预览图**，支持**多轮对话**修改。

> 关键设计：`prompt.md` 要求模型输出的是**代码（离散网格）**而非真实图像，
> 因此**纯文本模型即可胜任**；文生图模型无法保证 16×16、固定 16 色、透明通道与代码格式，不采用。

## 快速开始

```bash
npm install
npm run dev          # 启动服务
# 浏览器打开 http://localhost:3000
```

## 配置（`.env`）

| 变量 | 说明 | 默认值 |
|---|---|---|
| `DEEPSEEK_API_KEY` | DeepSeek API Key（写在 `.env`，不要提交到仓库） | 无 |
| `DEEPSEEK_BASE_URL` | OpenAI 兼容端点 | `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | 旧配置项，指定“仅 chat”档模型（保留兼容） | `deepseek-chat` |
| `DEEPSEEK_CHAT_MODEL` | “仅 chat”档模型，优先于 `DEEPSEEK_MODEL` | 同 `DEEPSEEK_MODEL` |
| `DEEPSEEK_THINKING_MODEL` | **思考档（快速/轻思考/深思考）模型**，需支持 `thinking` 参数 | `deepseek-flash` |
| `MAX_REPAIR` | 每次生成最多尝试次数（`auto` 档下即升级次数） | `3` |
| `TEMPERATURE` | 快速档首轮温度；仅 chat 档会随重试递增（思考模式忽略温度） | `0.3` |
| `MAX_TOKENS` | 快速档输出 token 上限 | `8192` |
| `THINKING_MAX_TOKENS` | 轻思考（low）档输出上限 | `16384` |
| `DEEP_THINKING_MAX_TOKENS` | 深思考（high）档输出上限；过小会被思考吃光导致截断 | `24576` |
| `DEFAULT_COST_LIMIT` | 新会话默认费用上限（人民币元） | `0.50` |
| `LOGS_DIR` | 每次尝试的原始输出落盘目录（便于排查截断/退化） | `logs` |
| `PREVIEW_SCALE` | 预览默认放大倍数（前端可切 8/16/32/64） | `16` |
| `PORT` | 服务端口 | `3000` |

> 模型名为 `deepseek-flash`（官方现名，支持深度思考）。旧 `.env` 中的 `DEEPSEEK_MODEL=deepseek-chat` 不用改，它只会影响“仅 chat”档。

## 使用说明

1. 左侧输入需求（如“画一个红色药水瓶”“尺寸 32*32 的宝箱”“复杂场景：森林地图”）。
2. 顶部选择**思考模式**（默认“自动升级”），并设置**本会话费用上限**；右上角实时显示 `已花 / 上限`。
3. 服务端调用 DeepSeek 生成 `img\`...\`` 代码 → 解析 → 校验（字符集/行数/每行像素数/图块数量/空图）→ 渲染 PNG。
4. 校验失败时，程序把**具体错误**（如“第 3 行有 17 个像素”）自动回传模型修复；`auto` 档还会按失败情况升级思考档位。
5. 右侧即时显示预览；下方可开关**像素网格线**、切换**放大倍数**、下载 PNG、复制代码；标题旁显示本轮实际费用与尝试次数。
6. **左侧对话的展示**：AI 输出的代码默认折叠（展开后为等宽字体）；思维链（若有）默认折叠；模型若附带简要介绍，会像普通对话一样显示。新消息/新会话会自动滚到最底部。
7. **失败重试**：生成失败时错误气泡提供两个按钮——
   - **按当前档位重试**：用刚才最后一次失败的档位（`fast`/`low`/`high`/`max`/`chat`）再调用 **1 次**，不会从快速档重新爬；
   - **升级后重试**：按 `chat/快速 → 轻思考 → 深思考 → max` 升级一档再试 **1 次**；已是 `max` 时按钮禁用。
   重试同样受费用上限约束，失败费用照常计入累计。费用上限不足（HTTP 402）时只提示调高上限/换模式，不显示重试按钮。
8. **多轮修改**：直接在左侧继续对话（“瓶塞改成软木色”）；或点击历史缩略图查看旧图，用 **“回到此轮”** 截断历史、从该图继续改。
9. 每轮 PNG 落盘 `preview/<session>/turn_NNN.png`，并生成 `preview/gallery_<session>.html` 画廊（顶栏“🖼 画廊”直达）。
10. 会话历史落盘 `sessions/*.json`（含设置与累计花费），刷新与重启均不丢。

## 思考模式与费用

### 三档模式

| 模式 | 调用策略 | 典型耗时 | 适用场景 |
|---|---|---|---|
| **仅 chat** | `deepseek-chat`，无思考；失败靠温度递增重试 | 2~5 秒 | 简单图标、快速迭代、最省钱 |
| **自动升级**（默认） | 快速（`deepseek-flash` 关闭思考）→ 轻思考（`low`）→ 深思考（`high`），逐次失败才升级 | 正常 2~5 秒；复杂场景 20~70 秒 | 日常使用，兼顾速度与成功率 |
| **深度思考** | 直接 `high`；重试时升到 `max` | 10~60 秒甚至更久 | 复杂场景、32×32、自动升级仍失败 |

升级由**程序校验结果驱动**：格式/空图/截断都会触发下一次尝试，因此“画不出来”时最多花费 3 次调用。实测森林场景在 `high` 档才能正确拆 tile。

### 费用计算

- 按官方 token 价格逐次计算：输入未命中缓存、缓存命中、输出分别计价；**失败尝试也计费**。
- 高峰时段（北京时间工作日 9:00–12:00、14:00–18:00）价格为空闲时段的 2 倍；法定节假日按工作日近似。
- 计费明细：每轮标题显示实际费用；顶部显示会话累计；画廊页脚显示累计花费。
- 价格表位于 `src/pricing.ts`（元 / 百万 tokens），官方调价时改这里即可。

### 费用上限（硬限制）

1. 每次调用前按“输入全未命中缓存 + 用满该档 `max_tokens`”估算**最坏费用**，超过剩余额度直接拒绝（HTTP 402），不会先花钱再报错。
2. 达到上限后，该会话所有生成都会被拒绝；在顶部调高上限、切到更省的模式或新建会话即可继续。
3. 上限是“最坏情况”守卫，实际费用通常远低于估算值（有缓存命中且不会用满输出）。
4. “回到此轮”会同步回退该轮之后的花费（被丢弃轮次不再占用预算）。

> 参考：一次简单 16×16 的快速生成约 ¥0.002；森林类 `high` 档多尝试一次约 ¥0.04~0.10；`max` 档可能单次超过 ¥0.1。

## 架构

```
public/   原生 HTML/JS/CSS 前端（无构建链）
src/
  server.ts   Express API（/api/chat、/api/session、/api/session/:id/settings…）+ 静态资源
  chat.ts     DeepSeek 调用 + system prompt(prompt.md) + 自动修复闭环 + 失败费用归集 + 思维链/介绍提取
  modes.ts    三档思考策略（chat / auto / deep）、逐次升档，以及失败重试可单独指定的档位 key
  text.ts     从模型原始输出中分离“代码”与“简要介绍”（介绍可像普通对话展示）
  pricing.ts  官方价格表、峰谷时段、token 费用计算与最坏情况预算
  parse.ts    提取 img`...` / CombinedTiles，重建规范化代码写回历史（容错多行/尾随逗号/自动推断布局）
  repair.ts   受限维度修复：只补齐/删除差 1~2 个透明像素，不移动内容
  validate.ts 字符集/尺寸/图块数量/空图校验，识别用户显式尺寸（32*32）
  render.ts   网格 → PNG（pngjs，最近邻放大，透明区棋盘格，多 tile 行优先拼接）
  palette.ts  prompt.md 规定的 16 色调色板 + `.`/`1`-`f` 映射
  sessions.ts 会话/设置/累计费用落盘与“回到此轮”截断
```

## 已知模型问题（已在程序侧兜底）

**DeepSeek 在低温度、关闭思考时，对“树 / 森林 / 草”这类提示会稳定输出全透明的空白画布**
（实测 `finish_reason=stop`，与长度截断无关）。程序侧的应对：

1. **空图校验**：全透明单图、任一全透明图块都会被判为无效并触发下一次尝试；
2. **自动升级思考**：`auto` 档从关闭思考开始，空白/格式失败后升到 `low`、`high`，实测可恢复出完整森林；
3. **温度递增重试**：仅“仅 chat”档使用（0.3 → 0.7 → 1.0），思考模式会忽略温度；
4. **强化修复提示**：空图错误会自动附加“把对象具体化、逐格绘制真实像素”的要求；
5. 原始输出、档位、`finish_reason`、token 用量与费用落盘 `logs/`。

注意：

- `deepseek-flash` **默认就开启思考（high）**，程序在快速档显式传 `thinking:{type:"disabled"}`，否则会意外变慢变贵。
- 思考模式下 `temperature` 无效，因此升级策略改为 `reasoning_effort` 升档。
- 思考 token 可能占输出 90% 以上；`high` 档建议 `max_tokens ≥ 24576`，`max` 档在复杂多图块场景容易耗尽 token 被截断。
- 思考能解决“画不出来/空白”，但**不能解决数错格子**；校验与自动修复仍必须保留。

### 自动修复层级（按成本从低到高）

1. **解析容错（免费）**：接受多行 `CombinedTiles`、尾随逗号、缺 `new`、`width=/height=` 写法；缺少拼接代码时，按用户显式尺寸（如 32×32 → 2×2）或完全平方图块数推断布局。
2. **维度修复（免费，受限）**：只处理差 1~2 个**透明**格的情况——补齐行尾缺失的透明像素、删除末尾多余空白行/多余透明点。绝不移动或删除有内容的像素；修复后仍要通过完整校验（空图仍会拒绝）。
3. **AI 结构修复**：本地仍无法解析时，把精确错误回传模型，并明确要求“只修代码结构、逐字保留像素行”，避免重画。
4. **思考升级**：自动升级模式下，每次失败后按 快速 → 轻思考 → 深思考 升档；格式问题会先收到“只修结构、保留像素”的精确提示。

> 实测 32×32 宝箱：第一次全透明被拒，第二次（轻思考）画出宝箱但多 1 个透明像素，本地修复后成功出图，35 秒 / ¥0.042。
